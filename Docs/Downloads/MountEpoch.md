# 原下载目录的显式重新授权

系统重新挂载同一 APFS 卷后，`st_dev` 可以改变。旧记录的设备号因此不能单独证明目录被替换，也不能自动作为新授权。搞门户只在用户通过正常目录选择面板重新选择原目录后，尝试一次完整的授权更新；未选择、选择取消或核验失败均不恢复下载。

## 身份条件

旧 `DestinationGrant.volumeUUID` 必须存在、是合法 UUID，并与当前所选目录的卷 UUID 相等。UUID 字母大小写不影响比较；缺失、非法或不同 UUID 不采用路径兜底。目录必须保持旧 inode，属于当前用户、没有组或其他用户写权限，并具有实际写入与搜索权限。每层路径以目录 FD 和 `O_NOFOLLOW` 打开，不接受符号链接。目录当前设备号与相关文件当前设备号必须一致。

原记录没有历史 UID 字段，所以实现核验的是当前目录、暂存目录和文件均由当前用户拥有；不声称比较了未曾保存的历史 UID。旧书签不用于自动重获授权，更新书签来自本次用户正常选择。

## 全部关联文件一起核验

`DownloadMountEpoch.prepare` 只接收此 grant 的完整关联条目集合，并返回不写盘的 `Plan`。Plan 持有本次选择的安全作用域与目录、文件 FD：

- 已完成产物必须是同一 inode、独立单链接的普通文件，字节数和完整 SHA-256 与旧记录一致。历史暂存设备号与 inode 如仍保留，须与该产物旧身份一致，且旧暂存文件名不能重新被占用。
- 部分下载必须保持暂存 inode。记录的已提交字节前缀须匹配已保存 SHA-256；文件可带有未提交尾部，Plan 对完整文件另作稳定摘要，重新授权过程不截断或改写尾部。零提交字节使用空内容摘要。
- 中断发布允许暂存名独存、最终名独存，或两个已知名字共同指向同一 inode。前两种只能有一个硬链接；最后一种只能有这两个硬链接。不同 inode、额外硬链接、缺失、长度或摘要不符均拒绝。
- 没有已记录文件身份的条目只能有零已提交字节。缺失、不可读、权限错误和任何不明确 I/O 状态都不会被当成空文件。

读取使用 `openat`、`pread`、`fstat` 与 `fstatat(AT_SYMLINK_NOFOLLOW)`。核验前后比较 FD 和名字对应的身份、所有者、权限、链接数、大小、标志及纳秒修改/状态时间。每次完整摘要之后，还会再次统一检查全部名字、FD 和应不存在的名字，避免核验后续大文件时忽略前面文件的变化。

## 提交边界与行为

对以前在本机授权的目录，启动恢复时也只读核对目录元数据。仅当原卷 UUID、inode、当前所有者和安全权限都匹配而设备号不同，才将原授权标为需要重新选择，并让未结束任务等待目录。此探测不打开关联文件、不截断尾部、不更新设备号或书签；其他异常仍按原恢复保护处理。所有已暂停或结束条目的操作菜单保留“重新授权原保存目录”入口。

Manager 必须先排除关联的活动传输、校验、排队或待自动重试，再将当前关联模型与最后持久化快照作比较。候选快照从该持久化快照构造；只替换这个 grant 及其关联条目所需的当前设备号、新书签、当前目录路径、规范 UUID 与重新授权标志，保留状态、字节数、inode、摘要和业务关联。

提交前及 Store 最终原子重命名边界再次调用 `Plan.validate()`，并核对模型与快照没有变化。只有完整 Store 提交成功之后，Manager 才发布相关内存模型。Plan 自身不写任何文件、不移动产物、不解析旧书签、不发起网络请求。更新后也不自动恢复、重试、排队或赋予会话自动下载权限；继续下载仍需用户明确操作。

Store 保留上一份完整快照。若原子重命名后的目录同步失败，可能已有完整新快照落盘，此时进入恢复保护并保留恢复依据，不把失败描述为“绝无写盘”，也不自动用旧库覆盖新资料。

此流程不改变下载数据库 schema、迁移例外授权入口或私人信任 pin。正常运行的 `DestinationAccess` 仍要求当前设备号和 inode 完全一致；没有静默容忍设备号变化的读取或写入路径。
