# 资料恢复保护与下载回送

## 主库与初始化

真正首次使用是资料路径不存在、没有独立初始化证据和历史设置。只有这种情况才创建初始网站。已有目录（包括空目录）、快照、附件、设置或初始化证据却缺 `library.json` 时，停止自动保存；不可读、损坏、未来 schema 与未完成事务也停止写入。窗口持续显示恢复状态，不把只读空白界面导出成新备份。

有效 schema 1 旧主库只建立独立证据，原文件、网站 ID、顺序、账号与 profile 绑定不重写。正常写入按事务阶段提交。中断后保留原资料与安全副本，不自动清除保护标记；须核对库、事务及对应证据后恢复，不保证仅复制一个文件就能解除所有中断状态。

## 请求幂等

门户账本保存收到、批准、执行和完成状态。schema 2 的账本 ID、代次与摘要由目录外的应用私有偏好证据约束；文件或整个 Journal/Exchange/资料目录被删，不会重新得到空历史。有效旧 schema 1 账本可事务迁移，未知执行状态记录为 `interrupted_execution`，不重放动作。

已有空 Journal 与“旧账本被删除”无法可靠区分，因此不自动按首次使用处理。需要恢复匹配的历史与独立证据；不提供静默清空历史的修复捷径。来源 bundle ID 和 nonce 只是声明，不是发送方认证。

V1.16 起，通用动作 Journal 与下载 Downloads 分别按各自独立证据检查。通用动作历史恢复受限时，仍不执行外部网站动作；独立下载账本有效时，可从网站右键发起本次下载交接，并接收已登记请求的结果。复制前检查请求类型、对应账本可用性与已知 `inReplyTo`，接纳前再次检查证据。结果界面明确提示不可用的历史类别，不把受限历史解释为空白。

## 搞下载提供方契约

目标必须是实际安装的 `com.gaoseries.GaoXiaZai`，并声明兼容的 `downloads.prepare` 能力。门户只发送用户本次复核的 HTTP/HTTPS 网址及能力表允许的媒体类型；含查询或片段先复核并允许去除，不读取或传递密码、Cookie、token、headers 或浏览器资料。提供方缺失或不兼容时，不创建下载任务，可由用户复制已复核的网址。

网站右键选择“交给搞下载复核…”后，复用上述隐私与目标确认，不改网站、账号或浏览器配置。接收方只声明 `file` 时，门户只提供该能力。保留的片段若不符合接收方规则，仍会被对方拒绝；不能把本地确认当作对方已接受。

出站请求以私有 `.gaoaction` 包保存，并在调用接收方前持久登记。LaunchServices 打开成功只说明包已交给目标 App，不表示接收方已接受任务或完成下载。

接收方每次回送使用新的结果 UUID，`kind=result`、`sourceBundleID=com.gaoseries.GaoXiaZai`、`targetBundleID=cn.mendao.launcher`、`action=downloads.prepare`，`inReplyTo` 对应门户原出站请求 UUID。沿用固定 GaoAction V1 的 UTC 120 秒 TTL、32 字节随机 nonce、尺寸和文件安全要求。门户在复制载荷前拒绝未知关联；复制后再复核任务与状态，且须用户确认才接纳。

1. 首次接受结果：`status=pending`，`provenance={"workflowState":"accepted","taskIDs":["opaque-task-id"]}`，无文件载荷和 references。任务 ID 必须非空、唯一、稳定，不能被挪用到另一请求。
2. 最终文件结果：先有已接受记录；使用新的结果 UUID，`status=completed` 或 `partial`，`provenance.workflowState` 必须与 `status` 完全相同，`taskIDs` 为已接受的同一任务集合。比如完成结果为 `provenance={"workflowState":"completed","taskIDs":["opaque-task-id"]}`。必须携带至少一个普通文件 item，实际长度及 SHA-256 与 manifest 一致，不能以空附件声称文件下载完成。
3. `failed`、`cancelled`、`unsupported` 为无文件结果，`workflowState` 同样必须与 `status` 相同；未建任务时 `taskIDs` 使用空数组，已绑定任务时不得换 ID。终态不能回退，重复结果只展示已有状态，不重放副作用。

当前实现接受独立整体结果，不接受额外分批 provenance 字段。文件经过固定 FD、有界私有复制、实际副本摘要核验后保留在门户自己的暂存，只有用户明确选择时在 Finder 显示；不自动打开、执行或覆盖文件。结果目录、来源声明、文件副本不授予其他原件的访问或删除权限。

`errorCode` 如存在，必须是 1–80 字节的 ASCII 小写字母、数字或下划线代码；不接受 URL、token、自由文本或控制字符。接收和持久记录重载均检查此边界。

当前结果界面展示聚合状态与已核验副本数量。提供方附带的 JSON 任务回执仍作为独立副本保留，不解析为逐任务界面。已收终态后，不同结果 UUID 仍拒绝；相同 UUID 与相同字节的有效包可去重。已过期包不能仅靠重复 ID 绕过有效期，接收方刷新终态包并不保证门户会再次接纳。

联调前重新核对实际安装提供方及能力版本，不能沿用历史“未安装”的结论。提供方未就绪时，只能验证门户契约和隔离 fixture。须双方实际安装后，再由用户明确启动冷启动、任务接收、最终文件回送和浏览器认证的实际验收；隔离检查或打开对方窗口都不是端到端通过。

## 构建与回滚

App 在生成前就位于 `.noindex` 容器；镜像核验挂载点与安装暂存也遵守相同边界。新完整备份保留资料、偏好、独立证据、助手绑定和原程序，验收后仍可按收据核对回滚；不删除安全备份来隐藏重复入口。旧格式收据继续核验原字段与原路径，不将缺失旧程序误认成当前新版。交付前须在实际用户会话确认正式安装路径同时出现在 Spotlight 和 LaunchServices 的有效结果中，其他旧登记按精确路径及本 App 标识处理。
