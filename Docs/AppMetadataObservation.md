# 新版程序根 MACL 的显式观察

此接口用于一次已发生的正常界面验收后、经明确决定接纳的程序元数据事实。它不把某个扩展属性通常由谁管理当作因果证据，不写入、删除或归一化属性，不授予文件或目录权限，也不放宽普通原件核验。

`Scripts/app_macl_observation.py` 只处理调用方传入的字节和完整程序记录。`parse_authority(raw, expectedSHA)` 要求私有事实文件与调用方独立提供的 SHA-256 完全相符；事实必须精确绑定原升级备份、原状态摘要、不可变链锚点/头、独立完整当前备份及其状态摘要、新版正式路径和前后完整程序身份摘要。原始 MACL 值只在私有事实与原件链中保存，不进入公共源码、App 或发行包。

唯一可接纳的变化是 `new` 正式程序根节点的 `com.apple.macl` 从原先不存在变为事实文件中明确指定的完整 72 字节值。Base64、字节数、内容 SHA 均须匹配。原根属性已存在、值不符、子节点同名属性变化、其他属性变化，以及内容、目录、inode、所有者、权限、ACL、flags 或其他任何完整记录变化均拒绝。旧程序原件不适用此观察接口。

`validate_transition(before, after, authority)` 对全部未知字段也进行 canonical JSON 字节比较，只有移除现记录中这一项新增根属性后，整份现记录才可与原记录完全一致。JSON 重复字段、非有限数值、布尔冒充整数、缺失字段或多余授权字段都不能被接纳。

外部安装器还必须核验真实签名、路径和原件、当前备份，以及原状态与链指针的实时一致性。明确接纳后，仅能追加不可覆盖的生命周期观察事件并正常推进其指针；原事件、原始身份记录、失败日志和现有属性保持。之后普通核验对追加事件封存的完整现记录仍严格全等，不自动接纳后续同名标签或不同值。

此纯校验模块本身不会访问文件系统、查询系统登记、追加事件或完成验收。没有明确事实文件与独立摘要时，默认完整原件比较行为不变。
